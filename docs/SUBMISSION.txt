========================================================================
6. SUMMARY
========================================================================

PROBLEM
  Harvest now, decrypt later: traffic protected by RSA or elliptic-curve key exchange can be recorded today and
  read once a large quantum computer exists. In our scan of 60 public Indian bank endpoints (one TLS handshake each,
  2026-10-29), 46 negotiated classical key exchange, 12 hybrid post-quantum, 2 were unreachable.

WHAT ATLAS DOES (7 steps)
  1 Detect        Find RSA / ECC / DH in code, configs and certificates (file:line evidence), plus live TLS probes
  2 Prove         Sign the Detect evidence into an ML-DSA-65 hash-chained Proof Chain before anything else runs
  3 Plan          Schedule the migration in weekly waves with a QpiAI Opt MILP, compared with FCFS and greedy
  4 Test          Gate each wave on real TLS 1.3 lab services: hybrid X25519MLKEM768, downgrade refused, rollback
  5 Cross-check   Check one week's cutover choice with QAOA on QpiAI QSV-Local against the exact optimum
  6 Verify        Sign every result and re-verify the whole chain
  7 Review        A person approves or rejects each result; the decision is signed too

========================================================================
7. ARCHITECTURE AND BACKEND
========================================================================

  Browser
     |  HTTP JSON API + Server-Sent Events (127.0.0.1 only)
     v
  atlas_web server (Python 3.12 stdlib HTTP, SQLite auth, CSRF)
     |
     v
  Pipeline runner (one subprocess per step, live log)
     |
     v
  Pipeline modules  --->  workspace files (out/, runs/)  +  signed ledger (ML-DSA-65, SHA-256 chain, Merkle root)

  7-step pipeline (contracts/stages.json):
  1 Detect (detect/) -> 2 Proof: findings signed (ledger/) -> 3 Plan (schedule/, QpiAI Opt MILP)
    -> 4 Handshake gates (capture/ + gates/) -> 5 Wave selection (qaoa/, QAOA) -> 6 Proof: post-quantum verified
    (ledger/ ingest + verify, contracts/ assemble) -> 7 Review (atlas_web review, signed decision)

BACKEND COMPONENTS

  atlas_web server  | atlas_web/        | Python 3.12 stdlib HTTP, SSE, SQLite, scrypt, CSRF | UI + JSON API, workspaces, roles
  Runner            | atlas_web/runner.py | subprocesses with timeouts                       | runs pipeline CLIs per workspace, live log
  Detect            | detect/           | static scanner + OpenSSL s_client probe            | RSA/ECC/DH inventory with file:line evidence, drift
  Schedule          | schedule/, solvers/ | QpiAI Opt MILP (local), FCFS, greedy             | weekly wave plan minimising weighted exposure
  Capture           | capture/          | OpenSSL 3.6.5 s_server / s_client -brief -msg     | real TLS 1.3 lab services + handshake evidence
  Gates             | gates/            | group allowlist, compatibility matrix              | PQ handshake, downgrade, compatibility, rollback per wave
  Ledger            | ledger/           | SHA-256 hash chain, RFC 6962 Merkle, ML-DSA-65 (OpenSSL CLI) | signs every run; detects any edit
  QAOA              | qaoa/             | numpy statevector, QpiAI QSV-Local (qpiai-quantum 0.3.0) | link cutover selection vs exact optimum
  Benchmark         | bench/            | same solvers, 6-16 variables                       | classical vs quantum vs hybrid
  Contracts         | contracts/        | JSON Schema                                        | validates outputs, assembles results.json, stage list

HOW TO RUN

  macOS / Linux:
    git clone https://github.com/Yojan-ui/q-shield-atlas.git && cd q-shield-atlas
    conda create -y -n pqc -c conda-forge python=3.12 openssl=3.6.5 && conda activate pqc
    pip install -r requirements.txt
    python -m atlas_web create-user --role admin
    ./run.sh                    # then open http://127.0.0.1:8000

  Windows (Anaconda Prompt):
    git clone https://github.com/Yojan-ui/q-shield-atlas.git && cd q-shield-atlas
    conda create -y -n pqc -c conda-forge python=3.12 openssl=3.6.5 && conda activate pqc
    pip install -r requirements.txt
    python -m atlas_web create-user --role admin
    run.bat                     # then open http://127.0.0.1:8000

  Tested on macOS (run.bat not tested on Windows; use WSL if anything fails). Without QpiAI keys the app runs on the
  local simulator and shows recorded results; a new pipeline run needs a free QPIAI_OPT_API_KEY in .env.sh.

HONESTY

  REAL: TLS 1.3 handshakes on the lab services and with 60 public bank endpoints; static scans of two public
        repositories at pinned commits; every solver run, signature and QAOA sample recorded with run_id and hashes.
  SIMULATED: the demo inventory (synthetic mock bank), migrations (planned, never applied to real systems),
        lab stand-ins for services, QAOA on simulators (one IBM ibm_fez hardware run, imported from a recorded package).
  ASSUMPTIONS: risk, effort and shelf-life values (config/assumptions.json), with a sensitivity test.
  No quantum advantage claimed: QAOA is a measured cross-check against the exact optimum.
  No key recovery, factoring or decryption anywhere. No QCloud job was created (subscription required).
